This audit closes only the professional right-inspector shell/hide/navigation foundation required by §53.8. It does **not** declare the whole §53.8 selection-context feature tree complete. Text-selection typography controls, image crop/replace/arrange controls and other object-specific properties depend on selection/editing models that are separate source-truth work.

## Source-truth requirement covered here

For this bounded requirement MALENJO must provide:

1. a real docked right-side contextual inspector;
2. compact inspector tabs for Properties / AI / Security / Comments / Sign;
3. per-document inspector tab state;
4. an explicit keyboard hide/show shortcut;
5. reclaimed document-canvas width when the inspector is hidden;
6. real PDF document/page context using already implemented state;
7. real navigation/actions for existing suite capabilities rather than decorative dead controls;
8. honest absence of unsupported text/image-selection controls until those selection models exist.

## Audit of `main` before this PR

Already present:

- a permanently docked PDF right-side pane;
- real document name/page/size/edit/history/view information;
- real PDF mutation controls for text/shape placement, forms, headers/footers, Bates numbering, page boxes and page operations;
- real MALENJO AI, Security Center, Sign workspace and PDF Comments panel elsewhere in the suite.

Gaps against §53.8:

- the right pane was permanently visible and could not be hidden;
- no inspector-tab model existed;
- no keyboard hide/show shortcut existed;
- hiding the pane could not reclaim document-canvas width;
- AI, Security, Comments and Sign were not represented through the canonical inspector-tab contract;
- there was no explicit separation between currently supported document/page context and future text/image selection contexts.

## Implementation

### Shared inspector contract

- `src/suite/shell/inspector.ts` defines the canonical tab set:
  - Properties;
  - AI;
  - Security;
  - Comments;
  - Sign.
- The same shared contract defines the browser-safe shortcut **Ctrl/Cmd+Shift+.**.
- Shortcut detection is isolated and unit-tested so future document workspaces can adopt the same behavior.

### PDF inspector behavior

- inspector tab and hidden/visible state live inside each mounted PDF workspace, so independent document tabs keep independent inspector state;
- Properties preserves the existing operational PDF inspector controls and adds clear current-page/selection/edit-state context;
- AI opens the existing MALENJO AI workspace through real shell navigation;
- Security opens the existing Security Center through real shell navigation;
- Comments opens the existing operational PDF Comments left panel;
- Sign displays the current signature-field count and opens the existing MALENJO Sign workspace;
- the toolbar exposes a real show/hide button;
- the document command bus exposes **Show/Hide right inspector**;
- **Ctrl/Cmd+Shift+.** toggles the active PDF inspector;
- hidden inspector state removes the right grid column, returning that horizontal space to the document canvas.

## Deliberate scope boundary

The canonical source says the inspector changes with selection. Current `main` does not yet have the full text-object/image-object selection and editing models needed for honest typography, crop, replace, arrange and similar controls.

Those controls are therefore **not** faked in this PR. They remain separate traceable work under §53.8 and the advanced PDF/Office editing source trees.

## Open-source / licensing decision

No new third-party dependency is introduced. This is original MALENJO shell/workspace orchestration around already selected dependencies.

No Adobe/Foxit code, icons, artwork, layouts or trade dress are copied.
