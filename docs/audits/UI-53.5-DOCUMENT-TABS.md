## Source-truth acceptance criteria

For this bullet MALENJO must provide:

1. persistent document tabs in the global/title layer;
2. multiple open documents;
3. independent document/editor state;
4. independent undo history for editors that currently support mutation;
5. visible dirty state;
6. visible saving/write state;
7. ordinary close controls;
8. middle-click close;
9. keyboard close;
10. keyboard switching between open documents;
11. multi-file opening without replacing the previously open document.

### Gap discovered by this audit

The shell had a `saving` state and the tab UI rendered a saving indicator, but PDF and Office export/write paths did not report their active write state to the shell. For mutating document types, the saving indicator therefore existed visually without being driven by those real write operations.

## Changes in this PR

- PDF export, selected-page extraction and split exports report write activity to their owning tab.
- DOCX/XLSX/PPTX export reports write activity to its owning tab.
- All write paths clear the saving state in `finally`, including error/cancel paths.
- Regression tests prove PDF histories remain independent across tabs.
- Regression tests prove Office histories remain independent across tabs.
- Regression tests prove browser/Codespaces multi-file registration creates independent document identities.

## Open-source / licensing decision

Reason: document-tab orchestration is MALENJO product-shell glue around already selected components, not a document engine. The canonical UI direction also requires original MALENJO identity rather than copying Adobe/Foxit trade dress or exact layouts.

Existing project dependencies and their already-recorded provenance remain unchanged.
