## Source-truth acceptance criteria

1. The central document canvas remains the primary workspace surface.
2. PDF canvas background is neutral dark gray/navy, not black and not saturated brand blue.
3. White pages remain clearly separated without excessive shadows.
4. Rendering work is prioritized in this order:
   - first visible page;
   - next/previous pages;
   - visible thumbnails;
   - remaining page/thumbnail/background work.
5. UI chrome must not make page one wait behind noncritical rendering work.

## Audit of main before this PR

Already present:

- a flexible central PDF canvas between the §53.6 left navigation and existing right inspector;
- PDF.js lazy page rendering using `IntersectionObserver`;
- lazy thumbnail rendering;
- first-page timing telemetry;
- a dark document workspace and white-page presentation.

Gap found:

- every `PdfPageCanvas` called `document.getPage(pageNumber)` for base-size discovery on mount, including far-offscreen pages;
- page-two/page-three thumbnail rendering was enabled immediately and could compete with first-page rendering;
- near/offscreen pages used one observer policy but there was no explicit source-truth render phase enforcing first visible → adjacent → thumbnails → remaining work;
- the central canvas used a blue-biased radial treatment and a comparatively heavy page shadow.

## Implementation

- Added `renderPriority.ts` with a deterministic scheduler:
  - focused/current visible page is always eligible first;
  - adjacent next/previous pages remain blocked until the focus page reports rendered;
  - noncritical pages remain blocked until the focus + adjacent critical pass reports rendered;
  - noncritical pages remain intersection-observer lazy even after the critical gate opens.
- `PdfPageCanvas` no longer calls `getPage()` for far-offscreen pages before its render phase is eligible.
- Existing print force-render still bypasses the interactive scheduling gates so full-document print remains functional.
- Thumbnail rendering is disabled until the critical page pass is complete; after that, existing thumbnail visibility/lazy behavior applies.
- Page-render completion is tracked per loaded working copy and reset whenever new PDF bytes are installed.
- Central canvas background is now a neutral dark gray/navy.
- White-page shadow was reduced and page separation retained with a subtle border.

## Scope and licensing

No Adobe/Foxit assets, layouts, icons or source code were copied.
