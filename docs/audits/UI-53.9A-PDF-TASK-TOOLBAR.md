This audit covers the PDF task-toolbar architecture required by §53.9. It does not claim that unsupported PDF features in the example Edit list already exist. Real text-object editing, image-object editing, stamp, measure, link authoring and other advanced PDF operations remain separate requirements.

## Source-truth requirement

MALENJO must use broad task categories above a focused command set instead of exposing every command at once. The canonical PDF category model is:

`Home | Edit | Convert | Organize | Comment | Sign | Protect | Forms | AI | Scan | Automate`

Tools may move to overflow as density requires. Keyboard shortcuts, Ctrl+K command search and accessible labels are mandatory. Discoverability must not depend only on recognizing an icon.

## Audit of main before this PR

Already present:

- an operational one-row PDF toolbar for Files/Open/Export/Undo/Redo/Print;
- page navigation and view controls;
- Ctrl+K command palette with several PDF commands and suite navigation;
- real PDF operations for page organization, permanent text placement, rectangle/highlight placement, comments and AcroForms;
- real suite routes for Sign, Security, AI, Scanner and Automation.

Gaps against §53.9:

- no broad task-category layer existed in the PDF workspace;
- all visible commands were mixed into one row rather than being filtered by task;
- no PDF task-category keyboard shortcut contract existed;
- no explicit overflow surface existed for lower-frequency page-organization actions;
- several operational PDF actions were not discoverable through Ctrl+K;
- unsupported Convert/Edit capabilities could not be distinguished structurally from implemented tools because there was no task-category model.

## Implementation

### Shared task-category contract

`src/suite/pdf/taskToolbar.ts` defines the exact canonical category order, labels, explicit Alt+Shift shortcuts and left/right/Home/End roving keyboard behavior.

Shortcuts are intentionally scoped to the active PDF workspace and ignored while the user is typing in form fields.

### Focused command sets

The task category selects only commands relevant to the current task:

- Home — Files, temporary Open PDF where appropriate, Export, Print, inspector visibility;
- Edit — Undo/Redo, configured permanent text placement, configured rectangle/highlight placement, edit settings;
- Convert — honest unavailable state because current main does not yet provide a complete PDF conversion provider;
- Organize — rotate, delete, duplicate, extract, split and insert as primary actions; append/blank/move commands in overflow;
- Comment — Comments panel and real /Text annotation creation;
- Sign — MALENJO Sign and current PDF signature-field panel;
- Protect — Security Center;
- Forms — add configured AcroForm field, flatten, form settings;
- AI — Malenjo AI;
- Scan — Scanner;
- Automate — Automation Studio.

Viewer controls remain persistent beside the focused command set because page navigation, zoom, view rotation and inspector visibility are document-view controls rather than task categories.

### Overflow

The first six task actions remain primary. Additional task actions render inside a keyboard-accessible `More` disclosure. This keeps lower-frequency organization commands out of the permanent primary row.

### Ctrl+K discoverability

Existing command-palette support is extended for operational Edit, Organize, Comment and signature-panel actions. Suite-level AI, Sign, Security, Scan and Automation navigation already existed in Ctrl+K.

### Accessibility

- category buttons use `role="tab"`, `aria-selected`, `aria-controls`, `aria-keyshortcuts` and roving tab focus;
- command rows use `role="toolbar"` and text labels;
- disabled commands expose the blocking reason in their accessible/title text;
- buttons use text labels rather than icon-only discovery.

## Deliberate scope boundary

The source gives an example Edit tool list containing Hand, Select, Edit Text, Edit Image, Add Text, Add Image, Highlight, Underline, Strikeout, Comment, Stamp, Shapes, Measure and Link.

Current main does not have the full visual object-selection/editing model required for several of those tools. This PR therefore does not create decorative or nonfunctional versions of them. Their feature requirements remain open under the advanced PDF source tree and §53.8 selection-context work.

## Dependency / licensing impact

No new third-party dependency is introduced. This is original MALENJO React/TypeScript/CSS orchestration around existing local PDF operations and existing suite navigation.

No Adobe/Foxit code, icons, artwork, exact toolbar arrangement or trade dress is copied.
