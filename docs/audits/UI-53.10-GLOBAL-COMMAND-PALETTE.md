# UI 53.10 — Global command palette audit

## Source

Canonical source: `MALENJO_SUITE_FINAL_MASTER_README.md` lines 4231–4249.

Canonical SHA-256: `e24c8f238c01bfd455f2d9994789feaa5b674ac167d191e678452fc3cf5b13aa`.

Tracking issue: #130. Parent UI/UX source issue: #121.

## Requirement

The canonical source requires `Ctrl + K` to be a suite-wide action/search surface that can find **actions, documents and settings**. It gives eleven example command phrases and explains that the palette is strategically important because MALENJO has a broad feature set.

## Gap found on main before this correction

The existing palette already opened with Ctrl/Cmd+K, searched several implemented actions and workspaces, and switched among already-open document tabs. It did **not** satisfy the complete 53.10 search contract because:

- documents that existed in the MALENJO library but were not already open were not indexed;
- Settings was not represented as a dedicated searchable setting destination;
- registered workspaces such as Invoice, CAD, DICOM, Settings, Account and Help were not all discoverable through the palette;
- matching required one contiguous substring, so natural multi-word searches across label/keywords/detail were unnecessarily brittle;
- canonical example phrases that are not operational in the current build had no explicit discoverability state.

## Implemented correction

### Actions and workspaces

Every registered MALENJO workspace is now discoverable through the palette. The existing document command controllers remain indexed for the active document, so implemented PDF/Office operations remain directly searchable.

The canonical example phrases are represented by a single source-aware contract in `commandPaletteModel.ts`. Operational destinations open the appropriate real workspace. Unsupported operations are **disabled discovery entries**, hidden from the empty/default palette and shown only when their phrase/keywords are searched.

This prevents fake capability claims while still making the source-truth command discoverable.

Current explicitly unavailable examples are:

- Compress this PDF;
- Convert to Word;
- Protect with password;
- Create invoice.

Those remain separate feature work. Their appearance in Ctrl+K is not an implementation claim.

### Documents

When the palette opens:

- Tauri/Desktop loads the current MALENJO library using `listLibraryDocuments()`;
- Codespaces/browser loads the current session library using `listBrowserDocuments()`;
- already-open documents remain represented as tab-switch actions;
- unopened library documents are represented as searchable document results;
- selecting an available desktop library result re-opens it through `openLibraryDocument()` before creating/activating a document session;
- unavailable indexed files remain searchable but disabled with an explicit reason.

This extends document search beyond only the current tab strip.

### Settings

The registered Settings workspace is now a dedicated `Settings` command-palette result with setting-specific iconography and search keywords. This is intentionally bounded to the currently implemented Settings foundation; individual future settings are not invented.

### Search behavior

Search now tokenizes the query and requires every token to match the combined label, group, keywords, detail or disabled-reason text. For example, a document can match by filename plus type and Settings can match by setting-related keywords.

Empty-query results exclude source-discovery-only unavailable commands so unsupported features do not crowd the normal command surface.

## Tests

`src/suite/shell/commandPaletteModel.test.ts` verifies:

- action search;
- library-document style search;
- Settings search;
- multi-token matching;
- hidden unsupported entries are absent from the empty palette but discoverable by query;
- every canonical 53.10 example has exactly one of an operational destination or an explicit unavailable reason.

## Legal / dependency impact

No third-party dependency, provider, model, binary, font or asset was added. This change is MALENJO-owned React/TypeScript shell orchestration and test code only.

## Completion boundary

This closes only canonical **§53.10 Global command palette** after CI and merge evidence are recorded.

It does **not** make the global shell complete, does not make Settings complete, and does not implement PDF compression, PDF-to-Word conversion, password protection or Invoice Studio. Registry module states therefore must not be promoted by this correction.
