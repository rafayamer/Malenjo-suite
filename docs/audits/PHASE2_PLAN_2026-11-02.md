**Status: NOT COMPLETED.**

Master Spec v2, Milestone 2 covers:
- page organization;
- the text editing foundation;
- annotations;
- watermarks;
- metadata;
- compression;
- scanning and OCR.

## Acceptance rule

A MAL capability becomes RELEASE_READY only through the **verified command adapter** (`src/suite/commands/verifiedCommands.ts`). A binding is accepted only when it meets every one of these:

1. Every clause of its requirement text in `docs/MALENJO_MASTER_SPEC_V2.md` is covered.
2. Each clause has passing acceptance checks that drive the real UI, save, and reopen the output independently with PDF.js and pdf-lib.
3. Those checks run in CI. `testing/suite/verifiedCommandEvidence.test.ts` fails if a cited check is missing.
4. Each PR has a clean Claude review and a clean Codex review, or every valid finding is fixed (owner policy, 2 Nov 2026).

Partial capabilities stay unbound and keep stating their limits.

## Slices

Each slice is one PR or more under the acceptance rule above.

1. **Done:** the adapter, its evidence register, and MAL-003–008 bound, with four new acceptance checks.
2. **Done:** MAL-001 multi-file ordered merge and MAL-002 split modes (ranges, page count, bookmarks, size).
3. **Done:** MAL-009 N-up (2/4/6/9/16 grids, sheet size and orientation, margin and spacing, row or column order) and MAL-010 batch assembly (ordered rules across files, ZIP with JSON/CSV manifest and SHA-256).
4. MAL-017–022: headers/footers, numbering, watermarks, metadata and outline, each bound with evidence.
5. MAL-024/025 compression and MAL-027/028 OCR/scanning.
6. MAL-054/055 annotations.
7. MAL-011–016 and MAL-023: the text editing foundation. This is the hardest slice. Each edit mode (native object edit, OCR reconstruction, overlay) must be labelled honestly.
