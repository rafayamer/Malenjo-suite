## 3. Product identity and immutable UX principles

MALENJO is first and foremost an enterprise PDF editor and manipulation suite for Windows desktop, browser/Codespaces validation and approved processing services. It is **not** an independent Word/Excel/PowerPoint suite, a generic administration dashboard or a decorative PDF preview. Office result editors are opened **only as a consequence of a successful PDF-to-DOCX, PDF-to-XLSX or PDF-to-PPTX conversion**. They allow review, correction, save and re-export of converted results, not standalone Office-product navigation or default file association.

The mandatory shell is one cohesive application window: compact top identity and quick actions, contextual ribbon, multiple document tabs, expansive interactive PDF canvas and compact status/navigation strip. No permanent left application-navigation rail. Optional thumbnails, bookmarks, search, annotations and document properties panels must be collapsible and closed by default where the specification says so. Put the product owner’s actual MALENJO logo and visible AI identity in their prescribed locations, preserving original files and verifiable provenance. Exactly two coherent themes, Light and Dark, based on existing MALENJO blue/cyan tokens; toggling themes must not alter document pixels or reset a session.

Home must center on actual **Open File** and **Recent Files** functions. Open invokes the real browser or operating-system picker and drag/drop; recent entries must reopen valid documents and handle missing sources honestly. Use lightweight first-party **static** folder/document and history icons. The owner explicitly removed the LottieFiles animation requirement; do not spend work on Lottie runtimes, WASM/CDN fixes, animation libraries or licensing for such assets. This later instruction supersedes conflicting animation wording in v2 only; the PDF 2.0 and 90-tool contracts remain untouched. Any remaining ordinary transitions must respect reduced-motion accessibility and must not introduce external network dependencies.

The ribbon must expose Home, Edit, Organize, Optimize, Convert, Forms, Review, Protect, Automate and Tools in a discoverable, keyboard-accessible fashion. An independent top-bar AI control should open a right-side contextual conversation without obstructing document actions. All user-facing commands need icons, names, tooltips, shortcut accessibility, command registry linkage, actual handlers or honest unavailable states. Responsive tests cover 1920×1080, 1440×900, 1366×768, 1024×768, 768×600 and narrower web layouts without clipping, unreachable actions, persistent overlay interference or uncontrolled horizontal scrolling.
